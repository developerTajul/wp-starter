# AI Task Orchestration Plan (v2.0): Unified Exception Handling, Atomic Rate Limiting & Transaction Integrity

## 1. Architectural Corrections & Core Requirements Summary

### 1.1 Zero Domain Leakage (The Golden Rule Enforcement)
- **Problem**: Making `ValidationException` a child of `HttpException` forces the Domain Layer to depend on the HTTP Layer.
- **Solution**: 
    - **Domain Layer**: Create `DomainValidationException` (extends `\DomainException`). Zero HTTP awareness.
    - **Infrastructure Layer**: Create `ValidationHttpException` (extends `HttpException`, status 422).
    - **Mapping**: The `ExceptionHandler` must map `DomainValidationException` $\to$ `ValidationHttpException`.

### 1.2 Atomic Rate Limiting (Preventing Race Conditions)
- **Problem**: Standard WP Transients/Cache are non-atomic, leading to race conditions under high concurrency.
- **Solution**: Implement `AtomicDatabaseRateLimiter` using atomic SQL operations (e.g., `INSERT ... ON DUPLICATE KEY UPDATE` or `UPDATE ... SET attempts = attempts + 1`).

### 1.3 Database Transaction Integrity
- **Problem**: Uncaught exceptions in the adapter may leave database transactions "dangling" (open).
- **Solution**: 
    - Create `TransactionManagerInterface` and `DatabaseTransactionManager`.
    - The `ExceptionHandler` must check `if ($this->transactionManager->inTransaction())` and trigger `rollback()` immediately upon catching any `\Throwable`.

### 1.4 Unified Exception Handler (Web & REST)
- Enhance `HttpException` with status codes/headers.
- Route both `Web` and `REST` adapters through a single `ExceptionHandler` to ensure consistent, formatted responses and no silent fatal errors.

---

## 2. Engineering Constraints & Guardrails

- **Strict Typing**: Every PHP file must start with `declare(strict_types=1);`.
- **Clean Architecture**: Domain Layer must have ZERO knowledge of HTTP status codes, headers, or WP globals.
- **SOLID**: Use Constructor Dependency Injection via interfaces.
- **Documentation**: Explicit English PHPDoc blocks for all classes and methods.
- **Complexity**: All logic must be evaluated for Time/Space Complexity (Big O).

## 3. Atomic Step-by-Step Execution Plan

### Phase 0: Codebase Discovery
1. Inspect `Request`, `Response`, `MiddlewareInterface`, `Pipeline`, `HttpException`, and Route Adapters.
2. Verify current service container and database handling implementation.

### Phase 1: Domain/HTTP Exception Separation & Unified Handler
- **Step 1.1**: Create `DomainValidationException` in the Domain Layer.
- **Step 1.2**: Upgrade `HttpException` and create `NotFoundHttpException` (404), `ValidationHttpException` (422), and `TooManyRequestsHttpException` (429).
- **Step 1.3**: Implement `TransactionManagerInterface` & `DatabaseTransactionManager` (supporting nested transactions via level tracking).
- **Step 1.4**: Implement `ExceptionHandler` (handles rollback $\to$ mapping $\to$ rendering).
- **Step 1.5**: Wrap `Web` and `REST` Route Adapters in a `try/catch` block delegated to `ExceptionHandler`.

### Phase 2: Atomic Rate Limiting & Middleware Integration
- **Step 2.1**: Create `RateLimiterInterface` and `AtomicDatabaseRateLimiter` using row-level locking SQL.
- **Step 2.2**: Implement `ThrottleRequestsMiddleware` (Signature $\to$ Limit Check $\to$ Header Attachment).
- **Step 2.3**: Register all bindings as singletons in the Service Container.

### Phase 3: Verification Audit
- [ ] Run `php -l` for syntax checks.
